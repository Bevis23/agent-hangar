## 一、这是个什么软件

你的 AI 助手们（Claude Code、Codex、ZCode、豆包、WorkBuddy……）每次干活都会在你电脑里建一个文件夹。时间一长，硬盘里到处是 `demo`、`test2`、`新建文件夹(3)`，谁也说不清哪个是哪个、哪个还有没提交的代码、上次动它是什么时候。

**Hangar（机库）是这些文件夹的统一管理台**，一句话定位：

> **统一管理电脑上所有 agent 的项目空间，并提供便携启动服务。**

它做三类事：

| 类别 | 具体能力 |
|---|---|
| 登记与整理 | 把散落各处的项目文件夹收进一屏卡片墙：分组、标签、收藏、搜索、筛选 |
| 到达与起飞 | 一键打开（资源管理器/终端/编辑器）；一键在指定文件夹里启动你的 AI |
| 感知 | 每个文件夹的 git 状态（分支、有没有没提交的）、AI 运行状态，实时可见 |

它**不做**的事（避免误会）：

- 不会删除、移动、重命名你的任何文件夹（全程只读）
- 不会上传任何东西（零联网、零账号、零遥测）
- 不编排 AI 任务（不调度多个 AI 并行干活——那是别的工具的事）

## 二、安装与启动

两种安装方式，任选其一：

| 方式 | 文件 | 说明 |
|---|---|---|
| 安装版 | `Hangar_0.3.0_x64-setup.exe`（约 2.1 MB） | 双击安装，无需管理员权限，只装给当前用户 |
| 绿色版 | `hangar-0.3.0-portable-win-x64.zip`（约 4 MB） | 解压到任意位置，双击 `Hangar.exe` 直接运行，不写注册表 |

要求：Windows 10/11。绿色版里还带一个 `hangar-cli.exe`（命令行工具，见第十二章）。

## 三、先认识五个词

| 词 | 意思 |
|---|---|
| **工作空间** | 就是一个普通文件夹。Hangar 只是"记住"它，不搬不动 |
| **登记** | 把一个文件夹记进 Hangar 的名册。移除登记 ≠ 删除文件夹 |
| **起飞** | 在某个文件夹里启动你的 AI 助手 |
| **启动配置** | 存在某个空间上的一条"启动配方"：用什么命令、开什么终端。配置好后卡片上会出现专属启动按钮 |
| **我的 agent** | 你手动告诉 Hangar 的 agent 清单（自动检测不到的那些），存进设置里，启动菜单永久显示 |

为什么叫"机库"：AI 助手像飞机，**飞机去哪飞是它的事，机库负责让每架飞机停得整整齐齐、随时能起飞**。

## 四、第一次使用：3 步上手

**第 1 步：把项目搬进机库**

1. 打开 Hangar，点右上角「**导入**」
2. 选你平时放项目的文件夹（比如 `D:\code`）
3. Hangar 自动扫描里面的项目文件夹，列出清单（默认全选）→ 可统一标记 agent 和标签 → 点「**导入 N 个**」

> 放心：这一步只是"做记录"，你的文件夹不会有任何变化。

**第 2 步：让 AI 起飞**

1. 找一张卡片，点「** 启动…**」
2. 菜单里点你想要的 AI（自动检测到的 + "我的 agent"里配置的）
3. 弹出确认窗，过一眼将要执行的命令 → 点「启动」
4. 屏幕上弹出一个**新的命令行窗口**，已定位到该文件夹，AI 就在里面等你

**第 3 步：以后一键直达**

启动过一次后，卡片上出现该 AI 的专属按钮（如 ` Claude Code`），以后**点一下就起飞**。点 `</>` 用编辑器打开该文件夹。

## 六、功能详解：登记与导入

**手动登记**：「＋ 登记空间」→ 选择文件夹 → 填名称、agent、标签、备注、图标、颜色、分组 → 保存。

**批量导入**（推荐首次使用）：

- 扫描你指定的目录（两层深度），按"项目特征"自动识别：文件夹里有 `.git`、`package.json`、`Cargo.toml`、`pyproject.toml`、`CLAUDE.md`、`.vscode` 等就算项目
- 已经登记过的自动跳过；`node_modules`、`target`、`dist` 等噪音目录自动排除
- 可统一给这批空间标记 agent（如"都是 Codex 建的"）和标签
- 单个失败的会列出原因，不影响其他

**编辑**：卡片 → 所有字段都能改，还能管理启动配置（见第九章）。

**移除**：卡片 → 第一次点击变红「确认？」→ 2.6 秒内再点才真正移除。**只删登记，不删文件夹**。后悔了：重新登记同一个文件夹，历史记录自动复活。

## 七、功能详解：整理

- **分组**：分组条「＋ 分组」创建（可带 emoji 图标）；编辑卡片时归入分组；分组条点胶囊即过滤；hover 胶囊出现 ×，两段式删除分组（组内空间自动变为"未分组"，不会被删）
- **标签**：每个空间可挂多个标签（逗号分隔），卡片上显示为 `#标签`，搜索可命中
- **收藏**：卡片 切换，收藏的永远排最前
- **排序规则**：收藏优先 → 最近打开的在前
- **搜索**：匹配名称、路径、agent、标签、备注
- **筛选**（右上两个下拉）：按 agent 筛（只看某个 AI 建的）｜ 按 git 状态筛（有未提交修改 / 工作区干净 / 非 git 目录）
- 所有条件可以**叠加**：比如"在干活"分组 + Codex + 有未提交修改

## 八、功能详解：打开（应用内文件浏览）

点卡片的 **浏览**：**全程不离开 Hangar**——右侧滑出文件浏览抽屉：

- 点文件夹进入下一层，面包屑随时跳回任意层级，`` 回上一级
- **点文件直接在应用内查看**（见下方"内置查看器"），不跳转
- 每行显示修改时间，文件显示大小
- 抽屉右上角「资源管理器」可随时跳出去

**内置查看器/编辑器**（点文件弹出的大窗口）：

| 文件类型 | 应用内体验 |
|---|---|
| Markdown（.md） | **渲染预览**（标题/列表/代码块/表格/图片都支持）＋ 一键切换"编辑"模式 |
| 文本类（txt/json/代码文件等 30+ 种） | 直接在应用内**查看和编辑** |
| 图片（png/jpg/gif/webp/svg 等） | 应用内直接预览 |
| 其他二进制 | 提示用系统默认程序打开 |

- **Ctrl+S 保存**（或点保存按钮），改动直接写回原文件
- 关闭时有未保存修改会提醒；超过 2MB 的大文件只显示前 2MB 并明确告知
- 每个查看窗右上角仍有「系统打开」，想用外部程序随时可以

另一个入口 </> 编辑器：用你配置的编辑器打开整个文件夹（需在设置里配一次命令，如 `code {path}`）。

想要命令行窗口：卡片「 启动…」→ 自定义命令输入 `powershell` → 得到一个停在该目录的命令行窗口。

## 九、功能详解：启动 agent（核心功能）

这是 Hangar 的灵魂功能，有三种用法：

### 用法 A：「 启动…」菜单（零配置，最常用）

每张卡片都有这个按钮，点开是一个菜单：

- **检测到的 agent**：Hangar 自动扫描你电脑装了哪些命令行 AI（Claude Code、Codex、Gemini、Qwen、Copilot、Aider 等 13 种），装了就列出来
- **我的 agent**：你手动添加的（见下方"如何添加我的 agent"）
- **自定义命令**：临时输入任意命令（如 `claude --continue`），回车即启动；点「存为常用」则永久进菜单

选一个 → 确认窗过目命令 → 启动：弹出一个**新的命令行窗口**，已定位到该空间目录并运行命令；**命令退出后窗口保留**。

启动成功后，这次的选择会自动存成该空间的启动配置——**下次卡片上就有专属启动按钮了**。

### 用法 B：预先配置启动配置（适合固定工作流）

编辑卡片 → 「启动配置」区：

- 点 `＋ Claude Code` / `＋ Codex` / `＋ Gemini CLI` 快速填入预设，或 `＋ 自定义` 输入任意命令
- 保存后卡片出现专属启动按钮

### 用法 C：命令行 `hangar run`（见第十二章）

**编队起飞（多空间同时开工，各飞各的）**：顶栏「编队」进入编队模式 → 点卡片左上角圆圈选多个空间 →「编队起飞」。弹出窗会列出**起飞计划**：有启动配置的空间直接用自己的配置起飞；没配置的空间才需要临时选一个机型。提示：豆包/WorkBuddy/ZCode 这类桌面应用是单实例的，编队只会唤醒同一个窗口——适合编队的是 claude/codex 这类命令行 agent。完事出报告"N 架已起飞"。

**时间机库（起飞前自动快照）**：每次 agent 起飞前（桌面端/CLI/MCP 三条路都算），Hangar 自动把工作空间打包快照（排除 node_modules 等依赖目录，每空间保留最近 5 份，单份上限 256MB）。卡片悬浮按钮里的 **⏪** 打开时间机库：看到每份快照的时间和体积，一键「回滚到此」——AI 把文件改坏了？回滚，10 秒恢复原状。**非 git 目录同样有效**（很多 agent 乱建的文件夹根本没有 git）。设置里可关闭此功能。

**运行状态与停止**：

- 运行中的配置按钮显示**绿色脉冲圆点**
- 点击运行中的按钮 → 变红「确认停止？」→ 再点一次 → 终止整个进程树（终端+AI 一起干净退出，用 `taskkill /T`）
- 状态每 2 秒自动刷新；AI 自己退出后按钮自动复原
- 同一配置同时只允许一个实例（防止开一排重复窗口）

**确认机制**：任何命令首次启动前都会弹窗展示**完整命令 + 终端类型 + 目录**，你点「启动」才执行；勾选「记住选择」后此配置不再询问（可在编辑里重置）。

**如何添加"我的 agent"**（自动检测不到的桌面版 AI，如 ZCode、豆包、WorkBuddy）：

- 方法 1：「设置」 设置 → 「我的 agent」→ 点「**选择程序…**」→ 浏览到它的 exe（一般在 `D:\软件\` 下）→ 完事
- 方法 2：任意卡片「 启动…」菜单 → 「**＋ 从电脑添加 agent…**」→ 选 exe
- 方法 3：在菜单自定义命令里输入完整路径启动并点「存为常用」

**预期行为说明**（不是 bug）：ZCode、豆包、WorkBuddy 这类**桌面应用是单实例**的——如果它已经在运行，再"启动"只会把已有窗口带到前台，不会开新窗口、也不会定位文件夹；这是它们没提供"指定文件夹启动"的命令行参数，任何启动器都绕不过。适合从 Hangar 一键起飞的是命令行形态的 AI（claude/codex 等），每次都是全新窗口+正确目录。

## 九点五、动态视图 + agent 贡献画像

顶栏「动态」切换到**塔台动态屏**：机库里最近 14 天发生的所有事汇成一条时间线——

- 起飞（谁在哪台跑）、git 提交、工作动态（agent 用 MCP 记的）、快照、打开
- 顶部**贡献画像**：本周每只 agent 干活的计数——"ZCode ×7 · 豆包 ×3"，多 agent 并行时一眼看清谁在出力
- 点时间线里的空间名直接跳回卡片墙并筛选

配合 MCP：agent 每次干完调用 `log_activity` 记一笔，时间线就是**自动生长的工作日志**。

**拖拽登记**：把文件夹从资源管理器拖进 Hangar 窗口，直接登记（自动打"拖拽"标签），不用点任何按钮。

## 十、功能详解：git 状态

卡片上的 git 分支名就是该文件夹的 git 状态：

| 显示 | 含义 |
|---|---|
| 绿色 `main` | git 项目，工作区干净 |
| 琥珀色 `main ~3` | git 项目，**3 个文件有改动没提交**（含新文件） |
| 不显示 | 该文件夹不是 git 项目 |

- 后台 8 线程并行查询，每 30 秒自动刷新，几十个空间也不卡
- 配合筛选器「有未提交修改」，一秒找出"哪些活还没收尾"

## 十一、功能详解：设置

点顶栏 「设置」 打开，即改即存（重开应用保持）：

**外观**

- 强调色：8 色任选（影响按钮、高亮、logo）
- 背景色调：午夜 / 深海 / 咖啡 / 森林 / 石墨 五套
- 背景图片：选一张本地图片当壁纸 + 遮罩浓度滑杆（保证文字可读）

**终端与编辑器**

- 编辑器命令：`code {path}` 模板，`{path}` 自动替换成空间目录

**我的 agent**

- 每行一条 `名字=命令`；「选择程序…」按钮可直接浏览选 exe（推荐）
- 路径写法：用正斜杠 `/`；含空格的路径用英文双引号包住
- **给单个 agent 指定终端**：行尾加 `|终端名`，例如 `豆包=D:/软件/豆包/Doubao/Doubao.exe|powershell`（可选 gitbash / powershell / cmd / wsl）；不加则用默认终端。启动菜单里该 agent 右侧会显示它用的终端

## 十二、功能详解：命令行 CLI

绿色版里的 `hangar-cli.exe`（可改名为 `hangar.exe` 放进 PATH）。**与桌面软件共用同一份数据**，可以混着用（比如在终端里登记、在图形界面里整理）：

```bash
hangar ls                     # 列出全部空间；hangar ls api 模糊过滤
hangar add D:\work\demo --agent claude-code --tag 实验 [--name 名字]
hangar open demo              # 资源管理器打开（模糊匹配名字）
hangar open demo --terminal   # 默认终端打开
hangar run demo               # 运行该空间第一条启动配置
hangar run demo --config "Claude Code"   # 指定某条配置
hangar star demo              # 收藏（再执行一次取消）
hangar tag demo rust web      # 追加标签
hangar rm demo                # 移除登记（软删除，不碰文件夹）
hangar config get             # 查看全部设置
hangar config set default_shell powershell   # 改设置
hangar mcp                    # 启动 MCP 服务器（下一章）
```

匹配规则：精确名字 > 唯一包含匹配 > 多个匹配时列出候选让你选精确的。

## 十三、功能详解：MCP——让 AI 操作机库

**MCP 是什么？**（方向要理解对：不是 Hangar 去"管理"AI，而是**把机库的钥匙发给 AI**）

配好之后，你直接在 AI 对话框里用自然语言指挥它操作机库：

> "列出我机库里所有的工作空间"
> "博客那个空间 git 状态怎么样？"
> "打开实验空间" / "在终端里打开它"
> "在博客空间里启动一个 claude"

更进一步，AI 还能**反过来帮你整理机库**：它建完新项目会自动登记，干完活往卡片上写一笔工作动态——**AI 越用，机库越聪明**。

**配置方法**（一次配好）：

```bash
claude mcp add hangar -- hangar mcp
```

或在支持 MCP 的工具配置文件里加：

```json
{ "mcpServers": { "hangar": { "command": "hangar", "args": ["mcp"] } } }
```

（`hangar` 需在 PATH 中，或写完整路径）

**AI 获得的 7 个工具**：

| 工具 | AI 能干什么 |
|---|---|
| `list_workspaces` | 列出空间（可过滤） |
| `get_workspace` | 查看某个空间详情（含 git 状态、启动配置） |
| `open_workspace` | 打开空间（资源管理器/终端） |
| `launch_agent` | 在某个空间里启动 agent（AI 可以启动 AI） |
| `add_workspace` | 登记新空间 |
| `upsert_workspace` | **自报家门**：AI 建完项目自动登记/更新（合并标签、标注是哪个 AI） |
| `log_activity` | **写工作日志**：往卡片备注追加"什么时间干了什么" |

**效果举例**：配置到 Claude Code 后，对它说"帮我建一个新项目 demo，做完登记到机库里"——项目建好、机库里自动出现新卡片，备注里写着时间戳和它干的事。

## 十四、数据、隐私与安全承诺

- **所有数据**（空间登记、分组、标签、启动配置、设置）都在本机一个文件里：`C:\Users\你的用户名\AppData\Roaming\hangar\hangar.db`
- **零联网、零账号、零遥测**：软件没有任何网络请求
- **对文件夹全程只读**：没有移动/重命名/复制/删除文件的功能
- **命令透明**：任何 AI 启动前展示完整命令，经确认才执行
- 卸载/清理：删掉安装目录 + `%APPDATA%\hangar` 文件夹即彻底清除

## 十五、常见问题 FAQ

**Q：会删我的文件吗？**
不会。全软件没有删除文件的功能；"移除登记"只删 Hangar 里的记录。

**Q：AI 正在跑，我关掉 Hangar 会怎样？**
AI 在独立窗口里继续跑，不受影响。重新打开 Hangar 后看不到它的运行状态（显示为可启动），但窗口本身还在。

**Q：点启动 ZCode/豆包没反应？**
单实例桌面应用：它会把已有的窗口带到前台。先完全退出它，再从 Hangar 启动试试。

**Q：终端/启动的窗口闪退？**
v0.3.0 起：终端全部自动选择（Windows Terminal 优先，PowerShell 兜底），无需也不支持手动选择；独立的「终端」按钮已移除。若仍遇到问题，请到仓库提 issue。

**Q：检测不到我的 agent？**
桌面版 AI（装在 D:\软件 之类）不走命令行，检测不到是正常的——用「设置 → 我的 agent → 选择程序…」手动加，一次永久生效。

**Q：误删了登记怎么办？**
重新登记同一路径，旧记录（含打开历史）自动复活。

**Q：编辑某个空间时它正在跑 agent？**
可以编辑，但该空间的启动配置会被重建，正在运行的那条会失去状态跟踪（AI 本身不受影响）。

**Q：支持 macOS / Linux 吗？**
暂不支持。技术栈是跨平台的，未来可能支持。
